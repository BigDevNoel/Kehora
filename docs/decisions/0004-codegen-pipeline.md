# ADR-0004: Codegen pipeline

- Status: accepted (approved in the Phase 0 plan)
- Date: 2026-10-30

## Context

CLAUDE.md rule 1: shared data shapes live as JSON Schema in `Backend/schemas/` and both
languages are generated by `make codegen`. The tools are not specified.

## Decision

| Output | Tool | From | To |
| --- | --- | --- | --- |
| Pydantic v2 models | datamodel-code-generator | `Backend/schemas/*.schema.json` | `Backend/schemas/kehora_schemas/generated/` |
| TypeScript types | json-schema-to-typescript | `Backend/schemas/*.schema.json` | `Frontend/packages/types/src/generated/` |
| OpenAPI document | FastAPI `app.openapi()` via `Backend/scripts/export_openapi.py` | API routes | `Backend/api/openapi.json` |
| TS API client | openapi-typescript (types) + openapi-fetch (runtime) | `Backend/api/openapi.json` | `Frontend/packages/api-client/src/schema.ts` |

- Schema files are draft 2020-12, one top-level shape per file, cross-file `$ref` by file name.
- Generated files are committed. `make codegen-check` regenerates and fails on any diff; CI runs it.
- `kehora_schemas/__init__.py` is the only hand-written file in that package: it re-exports
  the generated names so imports don't depend on generated module names.

## Consequences

Changing a shape means editing JSON Schema, running `make codegen`, and committing both sides.
API request/response models that are API-only (not shared with agents) stay as Pydantic
models in `kehora_api` and reach TypeScript through OpenAPI.
